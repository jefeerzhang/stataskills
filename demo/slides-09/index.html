同一个 y，为什么不能总用同一条命令？

两个政策问题都用面板数据，被解释变量都叫 y。
第一个能用 xthdidregress 估，第二个用同一条命令会直接报错。
差别不在数据有多少，而在处理变量本身怎么变。

这节课的顺序

  • 先看两个政策，弄清它们哪里不一样
  • 再看把两者弄混会出什么事，有两种混法
  • 最后是命令、参数和数字

复现基线

StataNow 19.5 MP（revision ≥ 2026-07-29，含 xtswitchdid）

先看两个具体的政策

两个县，两种处理

政策甲：给县通高速公路政策乙：给县评信用等级
取值通了 / 没通（0/1）三档：0 / 1 / 2
会不会变回去不会。路修好了不会拆，通了就一直通会。可以升档，也可以掉回来
具体例子甲县 2014 年通车，此后一直通乙县 2015 年是 2 档，2018 年掉回 0，2020 年又到 1 档
你想知道什么通车让这个县的 GDP 涨了多少每升一档，银行贷款成本降多少

两个问题都能用面板数据估。但能用的命令不是同一条， 差别出在乙县 2018 年那次「掉回 0」。

说明：报告用的是模拟数据，变量就叫 y 和 treat。 「通高速 / 信用等级」是教学类比。这个类比不是随手编的：报告场景 A 的处理年份正是 2014 和 2017 两批， 场景 B 的 dose 正是 {0,1,2}，其中有县先升到 2 档、再撤销回 0。

「处理前」到底指哪一年？

「通车前」= 2010–2013。只有这一个答案。

对照县从来没通车，一直停在未处理状态。 处理前后的分界只有一条，所以能直接算 ATET。

唯一
处理一旦开始就不再变，处理前只有一个年份

乙县（信用等级）

2014 2015 2016 2017 │ 2018 2019 │ 2020 2021

2    2    2    2   │  0    0   │  1    1

「升级前」是哪一年？2014？2017？还是 2019？

也很难找到一直没评过级的县来做对照，因为大多数县都在动。 处理前不唯一，只能按每个县走过的路径拆开看。

不唯一
处理可以撤回，处理前不是一个确定的年份

政策甲 · 吸收型错时

通高速的数据，用 xthdidregress

  • 400 个县 × 12 年（2010–2021），N=4800
  • 2880 个县从未通车；960 个县 2014 年通车；960 个县 2017 年通车
  • 各县通车年份不同，但通了之后不会再变回去
* 数据：data/did-routing/absorbing_staggered.dta

政策乙 · 多值可逆

信用等级这件事，用 xtswitchdid

  • 250 个县 × 20 年（2006–2025），N=5000
  • 等级 dose ∈ {0,1,2}，样本里有县升档之后又掉回来
  • 没有一直停在 0 档的县做参照，所以改问：每升高一档，效果有多大
* 一类县 2018 才撤销（首次处理后第 7 暴露期）→ neffects(7)
use "data/did-routing/switching_multivalued.dta", clear
xtset id year
xtswitchdid (y x1) (dose), group(id) neffects(7)
estat ptrends

错法一 · 把乙当甲

把「评过级没有」压成 0/1，命令报错了

你会这么想

乙县 2018 年掉回了 0 档。如果只关心「评过级没有」，可以把它压成 0/1：

* 只要等级大于 0，就算「被处理过」
gen byte treat_bin = (dose > 0)
xthdidregress aipw (y) (treat_bin), group(id)

Stata 的回答

invalid treatment
The treatment is assumed to be staggered. Once a unit is treated,
it should remain treated.
r(498)

命令在说什么

乙县 2015 年是已处理，2018 年又变成未处理。 命令据此判断数据违反了「一旦处理就永久处理」这个前提，于是拒绝往下估。

这是好事

它没有硬算出结果，而是直接停下。这样你会马上发现命令选错了。

正确反应

要换的是命令族，不是选项。 xtdidregress / xthdidregress 这一族按设计就不支持可逆路径， 加 if 或 option 都没用。 可逆数据要用 xtswitchdid，见第 5 页。

错法二 · 更危险的那一个

这次不报错，但你掩盖了撤销

你会这么想

乙县升过级又掉回 0。那我干脆标记「这个县曾经被处理过」， 首次处理后整段时间线都算处理组：

* treat_abs = 截至当期曾 dose>0 → 首次处理后永久置 1（掩盖撤销）
* bysort id (year): gen treat_abs = sum(dose>0) > 0
xthdidregress aipw (y) (treat_abs), group(id)
estat aggregation, overall
返回码_rc = 0 正常结束，没有任何警告
Overall ATET−1.013
se0.116
首次处理前误标 10（不是偷看未来）
撤销后仍标 1352

问题在哪

treat_abs 是「截至当期曾经处理过」：首次处理之前不会被标 1，这份数据里误标 0 个观测。 错在后面——乙县 2018 年已经掉回 0，变量却还是 1，撤销和剂量升降都被抹掉了。 估出来的 −1.013 不是当期每单位 dose 的效应。

−1.013
命令正常出数，估的却是另一个对象。错因是变量把撤销抹平了。

和第 6 页对照着看

第 6 页的命令报错，你会立刻去改。 这一页的命令不报错，如果不去核对变量的实际含义，很容易把 −1.013 直接写进论文。
判断命令有没有选对，不能只看它是否报错。

反过来 · 甲的数据用乙的命令

能跑通、也不报错，就说明命令选对了吗

xtswitchdid (y) (treat), group(id) neffects(4)
estat total                              // ≈ 2.150

xtswitchdid (y) (treat), group(id) neffects(8)
estat total                              // ≈ 2.349 ≈ AIPW 2.334
2.349
neffects(8) 的 estat total；短窗 neffects(4) 只有 2.150
HeaderAbsorbing = Yes 命令自己认出来了
报告的量normalized exposure effects
不是 AIPW 的 ATET 表
短窗 vs 长窗2.150 → 2.349：差额主要来自暴露期截断

两个数字接近，量的是同一个东西吗

不完全是。量的是两个不同的目标参数。 短窗 2.150 和 AIPW 2.334 的差距里，有一部分来自 neffects 截断，不全是定义差异。 窗口拉到 8 期后 total≈2.349，已经和 AIPW 很接近，但两个量各自的定义仍然要写清楚。

写论文时，主表如果声称的是 ATET 或事件研究聚合， 就用 xthdidregress aipw。 xtswitchdid 可以放在稳健性部分，但表头要写清报的是 normalized exposure 还是 ATET，以及 neffects 取了多少。

命令能跑通、数字又接近，都不能说明识别是对的。 第 7 页和这一页的两种错法成因不同，但都属于「看起来正常、实际估错了对象」。

路由卡 · 投稿前过一遍

看处理怎么变，再核识别条件

  1. 通了就不会变回去，各县开通年份不同
    xthdidregress aipw
  2. 能升也能降，或者档位在三档以上
    xtswitchdid
  3. 连续剂量 / HAD，不是离散档位
    did_multiplegt / did_had（社区包）

处理形态只决定候选命令。目标参数、同初始水平的对照、平行趋势与无预期，都要能辩护。 estat ptrends 没有拒绝，不等于假设成立。

自检

  • 处理编码和数据里实际的变化方式一致
  • 目标参数、对照、平行趋势与无预期都能辩护
  • 吸收错时：主表是 AIPW + 动态聚合，不是 plain TWFE
  • 可逆 / 多值：neffects 盖住撤销期，未压成 0/1；见 r(498) 就改命令族
  • 表头写清报的是 ATET、normalized exposure 还是 estat total
